# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Naive datetime replacement ignores IST timezone; checks `minutes > 10` where `minutes = int(diff_sec / 60)`. For `09:40:01` (601s), `minutes = 10`, so `10 > 10` evaluates to `False` returning 0. | Punch in at 09:40:01 for a 09:30 shift: expected `late_minutes = 10` (R2), but returned 0. | Normalized timestamps to IST using attendance date, checked `diff_sec > 600` strictly, and returned `diff_sec // 60`. |
| 2 | `compute_work_hours` | Uses Python built-in `round(..., 2)` which uses banker's rounding (round-half-to-even) instead of exact half-up rounding (R4). | A duration of 9630 seconds = 2.675 hours produces `2.67` with `round()` instead of `2.68`. | Implemented `round_half_up` using `decimal.Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | Overtime 30-minute minimum threshold (R3) was not enforced; shift end calculation on overnight shifts used the same calendar day instead of next day. | Punch-out at 18:35 (5 min after 18:30) returned 5 instead of 0; overnight shift (22:00-06:00) calculated negative/erroneous deltas. | Added overnight shift detection adding 1 day to shift end date; enforced `diff_sec >= 1800` threshold (returning 0 if under 30 minutes). |
| 4 | Startup database indexing | No database indexes were created on `employees` or `attendance_logs`. | Duplicate employees and duplicate punches could be created concurrently; explain plans showed `COLLSCAN` across all queries. | Added idempotent index creation in FastAPI `lifespan` for unique constraints and multi-key query support (`IXSCAN`). |
| 5 | `POST /employees` | Check-then-insert pattern causes race condition on concurrent duplicate requests; allowed `shift_start == shift_end`; used local naive `datetime.now()`. | Concurrent requests with same `emp_code` both returned 201; creating with `shift_start == shift_end` succeeded instead of returning 422. | Enforced unique index on `emp_code` and handled `DuplicateKeyError` (409); added validation for shift times (422); stored UTC timestamp truncated to seconds. |
| 6 | `GET /employees` | Pagination off-by-one (`skip = page * page_size`); `total` counted entire collection ignoring query filters; missing sort order. | Requesting `page=1` skipped the first 20 records (returning page 2); `total` ignored `department` filter; results were unsorted. | Changed pagination math to `skip = (page - 1) * page_size`, filtered `count_documents(q)`, and sorted by `emp_code` ascending. |
| 7 | `POST /attendance/punch-in` | Check-then-insert race condition; naive timestamp parsing; missing whole-second truncation (R1); missing overnight shift date logic; crashed with 500 if employee not found; injected non-standard `"id"` field. | Concurrent punch-ins created duplicates; unknown employee threw 500 `TypeError`; overnight punch-in at 05:45 IST was assigned to current day instead of previous day. | Added 404 for unknown employee; implemented R1 overnight shift date calculation; truncated timestamps to seconds; caught `DuplicateKeyError` (409); removed `"id"` injection. |
| 8 | `GET /attendance` | Loaded entire collection into Python memory (`find(q)`) and sorted/paginated in memory; no validation for `date_from > date_to`; unformatted BSON date serialization. | High memory consumption and severe latency on 100k documents; invalid date range did not return 422; punch instants returned as datetime objects instead of epoch ms. | Utilized MongoDB `.sort([("date", -1), ("emp_code", 1)]).skip().limit()`; added date validation (422); serialized all instants to integer epoch milliseconds. |
| 9 | `GET /health` | Statically returned `{"status": "ok"}` without verifying database connectivity. | Stopping MongoDB still resulted in `/health` returning 200 OK instead of 503 Service Unavailable. | Executed `db.command("ping")`, catching exceptions and returning 503 if unreachable. |
| 10 | `POST /attendance/punch-in` status validation | Accepted arbitrary status strings (including `ABSENT` / `LEAVE`) for punch-in. | Client could punch in with `status="ABSENT"`, creating invalid documents with punch times. | Restricted `status` to `PRESENT`, `WFH`, and `ON_DUTY` via Pydantic regex pattern (returning 422 on invalid status). |
| 11 | `EpochMillis` type validation | Accepted floats, numeric strings, and timestamps in seconds without strict typing. | Passing float milliseconds like `1783312500000.5` or second integers was accepted instead of returning 422. | Defined `EpochMillis` with `strict=True` and millisecond bounds `[100000000000, 4102444800000]`. |
| 12 | Internal `_id` leakage | Responses directly exposed or converted MongoDB's internal `_id` field. | API responses leaked MongoDB ObjectID `_id` in employee and attendance endpoints, violating API contract conventions. | Stripped internal `_id` and legacy `"id"` fields in `serialize_doc()` before returning JSON. |

### Items Inspected and Verified as Non-Defects

1. **`IST = timezone(timedelta(hours=5, minutes=30))`**: The timezone definition correctly represents Indian Standard Time (UTC+05:30) with no daylight saving shifts.
2. **`load_dotenv()` at top level**: Correctly loads environment variables from a local `.env` while preserving system environment variable precedence.
3. **Pydantic Model Dump Usage**: Using `.model_dump()` rather than deprecated `.dict()` conforms to modern Pydantic v2 conventions.
4. **Use of PyMongo synchronous client in FastAPI sync route handlers**: Standard FastAPI sync endpoints (`def ...`) are run in a threadpool worker by Starlette, avoiding blocking the main event loop while maintaining synchronous PyMongo compatibility.
